SR04_STOPWATCH 사용 안내
현재 버전: v0.8.0 — 팀의 단일 공용 UART에 직접 연결
변경 이력: CHANGELOG.md
팀 TOP 연결 예시: SR04_TEAM_CONNECTION.md

1. 구조

공용 UART는 팀 전체 TOP에 하나만 둡니다.
SR04_STOPWATCH에는 UART RX/TX가 들어 있지 않습니다.
별도 top_sr04_uart.v와 sr04_command_adapter.v는 더 이상 사용하지 않습니다.
팀 TOP은 담당자가 기존 파일에 우리 모듈의 인스턴스와 배선만 추가합니다.

2. 우리 모듈에 필요한 Design Sources

  sr04_stopwatch.v
  stopwatch.v
  sr04.v
  sr04_message_formatter.v
  sr04_uart_request.v

우리 블록을 단독으로 볼 때 Design Top: sr04_stopwatch
최종 팀 통합에서는 기존 팀 전체 TOP을 Design Top으로 사용합니다.
공용 uart_comm.v, uart_rx.v, uart_tx.v, fifo.v는 팀 원본 그대로 사용합니다.
같은 파일이나 같은 이름의 모듈을 중복으로 추가하지 마세요.
원본 FIFO의 control_unit 등과 다른 동명 모듈이 충돌하면 팀 담당자와 조율해야 합니다.

3. 공용 UART 연결

입력:
  comm[47:0], comm_valid: 공용 명령과 새 명령 알림
  rx_busy: 공용 UART가 메시지 송신 중이면 1
  sw_accept: 우리 전송 요청을 수락했다는 1클럭 펄스
출력:
  sw_req: 1클럭 송신 요청
  sw_msg[239:0]: ASCII 메시지
  sw_len[5:0]: CR/LF 포함 전송 바이트 수

r_pulse 외부 입력은 제거했습니다. SR04 내부에서
comm_valid && (comm == {"ss_r", 8'h0d, 8'h0a})를 확인해 토글합니다.
공용 UART의 기존 r_pulse 출력은 이 모듈에 연결하지 않습니다.

PC에서 보내는 명령:
  첫 ss_r + CR/LF: 초기화 후 시간·거리 측정 시작
  다음 ss_r + CR/LF: 정지, 시간·마지막 완료 거리 저장
  다음 ss_r + CR/LF: 초기화 후 다시 시작
원본 공용 UART는 단일 r을 외부 명령으로 내보내지 않습니다.
단일 r을 쓰려면 공용 담당자가 해당 명령이나 수신 바이트 출력을 지원해야 합니다.
다른 모듈의 dw_r + CR/LF는 SR04가 무시합니다.

4. FPGA 스톱워치와 표시

btn_run_stop, btn_clear, btn_mode, btn_lap은 디바운스된 1클럭 펄스를 받습니다.
FPGA와 UART의 시간 카운터는 독립적입니다.
FPGA Clear는 시간과 Lap을 초기화하되 실행/정지와 UP/DOWN 상태는 유지합니다.
Lap은 표시만 고정하고 내부 시간은 계속 카운트합니다.
data[15:0]는 FND용 임시 네 자리 packed BCD입니다.
팀 FND 입력 규격을 확인하고 팀 TOP의 모드 선택 MUX에 연결합니다.
SR04 모드에서 거리, 그 외 이 블록의 표시에서는 FPGA 시간을 선택합니다.
시간 표시는 display_mode로 초:1/100초 또는 시:분을 선택합니다.

5. 결과와 메시지

정지 때 result_msec/sec/min/hour/distance를 저장하고 result_valid를 1클럭 출력합니다.
result_msec는 10ms 단위(0~99)입니다.
정지를 수락하는 클럭에서 보이는 시간을 저장합니다.
같은 클럭에 완료 거리가 들어오면 해당 거리를 포함합니다.
재시작/FPGA 조작에도 저장 결과는 유지되며 다음 정지나 리셋에서 갱신됩니다.

시작 메시지: start_stopwatch\r\n (17바이트)
정지 메시지: stop_DDDcm_hh:mm:ss.cc\r\n (24바이트)
예: stop_099cm_00:00:00.01\r\n
첫 문자는 sw_msg[239:232], 다음 문자는 [231:224]입니다.
\r\n은 실제 CR(0x0D), LF(0x0A)이며 길이에 포함합니다.
사용하지 않는 뒤쪽 0 바이트는 전송하지 않습니다.
센서 실패 표시값 400도 현재는 400cm로 출력합니다.
message/message_len/message_valid는 중간 확인용이며 UART에는 sw_*를 연결합니다.

메시지 대기열은 최대 4개를 순서대로 보관합니다.
rx_busy=0에서 요청하고, UART가 요청을 받은 상승 엣지에서 내용을 복사한 뒤
sw_accept를 등록 출력하면 다음 엣지에서 수락을 확인합니다.
수락 전까지 내용과 길이를 유지하며, 미수락이면 재시도합니다.
수락과 동시에 UART가 자기 복사본으로 송신해야 합니다.
가득 차면 기존 메시지를 보존하고 새 메시지를 버립니다.
tx_queue_full은 포화 상태, tx_overflow는 폐기 발생 이력을 리셋까지 표시합니다.
수락과 새 메시지 입력이 같은 클럭이면 빈자리를 즉시 재사용합니다.

6. 단독·통합 시뮬레이션

Simulation Sources와 Top:
  tb_sr04_stopwatch.v -> tb_sr04_stopwatch
    제어·결과 저장·메시지·가짜 UART 연결 테스트
  tb_sr04_message_formatter.v -> tb_sr04_message_formatter
    ASCII 단독 테스트
  tb_sr04_uart_request.v -> tb_sr04_uart_request
    busy·재시도·FIFO·포화·리셋 단독 테스트

실제 UART RTL과의 연결 검증:
  Simulation Sources: tb_sr04_shared_uart.sv
  Simulation Top: tb_sr04_shared_uart
  공용 원본 UART 네 파일도 프로젝트에 등록되어 있어야 합니다.
  테스트벤치 안에 UART와 SR04를 나란히 두고 연결합니다.
  이 테스트벤치는 팀 설계 TOP이나 보드 회로로 합성하는 파일이 아닙니다.
  .sv는 문자열 비교용 SystemVerilog이며 Design Sources는 Verilog입니다.

Run Behavioral Simulation 후 run all을 입력합니다.
테스트 완료 후 $finish가 나오면 run all을 다시 입력하지 마세요.
직렬 테스트는 100MHz·9600bps로 수십 ms를 시뮬레이션해 기존보다 오래 걸립니다.
직렬 테스트 성공 문구: ALL SERIAL UART INTEGRATION TESTS PASSED
기존 단독 테스트 성공 문구는 유지합니다.

7. 검증 범위와 남은 작업

이전 버전 v0.4까지는 사용자 Vivado 단독·통합 테스트 통과를 확인했습니다.
이후 버전은 변경 이력에 해당 버전의 검증 상태를 구분해 기록합니다.
현재 버전은 Icarus에서 검사하며 Vivado v0.8.0은 사용자 확인이 필요합니다.
실제 UART RTL의 RX/TX 직렬 신호를 테스트벤치가 주고받습니다.
센서는 가상 ECHO 펄스로 대체합니다. 실제 PC/보드와 전체 팀 TOP은 미검증입니다.

남은 작업:
  - 실제 팀 TOP의 버튼/명령/송신 배선 연결 및 Watch/DHT/FND 전체 통합
  - 팀 FND 데이터 형식과 공유 UART의 최종 인터페이스 확인
  - 실제 보드와 PC 송수신 검증, XDC 핀·100MHz 클럭 제약
  - 외부 비동기 입력의 동기화 및 센서 전압 연결 확인
  - 센서 TRIG 최소 10us 보장
  - 빠른 재시작 때 이전 센서 결과가 섞이지 않도록 세션 처리
  - UART 정지 중에도 SR04 선택 시 거리 표시가 필요하면 측정 제어 추가

카운터와 Tick 설정은 100MHz 기준입니다.
이 안내는 보드 검증 완료를 의미하지 않습니다.
